CUB Film is a catalog of arthouse films. Visitors create an account, browse and filter the films, read about directors and genres, and keep a list of favorites. I built it during my full-stack course without starter code, and then wrote the client a second time in a different framework.

The server

The server is a REST API in Node.js and Express. Films and users are stored in MongoDB and modeled with Mongoose. Login and every protected route use JWT authentication. I tested the endpoints in Postman, then deployed the API to Heroku with the database on MongoDB Atlas.

First client, in React

The React client uses React Router for navigation and talks to the server through Fetch with token headers. It is assembled from a few reusable parts: film cards, dialogs, forms and a profile view. Users can register, log in, edit or delete their profile, and add or remove favorites.

This is where I learned the most. React was new to me, and routing, lifting state and error handling all arrived at once. The hard parts were debugging the connection between client and server, and getting a complete login flow to work with real tokens.

Second client, in Angular

A few months later I rebuilt the client in Angular and TypeScript against the same server. Before writing code I mapped the views and routes with user stories. The app is split into a main view, film cards, dialogs for director and genre details, and a profile section. Routing, form validation and the calls to the server sit in their own services.

Angular suited me. Its separation of concerns gave the project a structure I had needed to invent for myself in React, and I organized the SCSS around design tokens from the start.

What I would change

The React client was my first, and it shows. Today I would split its components further and restructure them so the app could grow.
